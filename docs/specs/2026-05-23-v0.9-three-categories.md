# v0.9.0 — 3 카테고리 × Top 10 출력 모델

**날짜**: 2026-05-23
**입력**: 사용자 요청 — 단일 추천도 Top 10 모델에서 카테고리별(종합 / 딸깍 / 자본X) Top 10 모델로 전환. 자본 deploy hard exclude 해제하고 ranking에 포함.

## 동기

v0.7-v0.8까지 사용자 프로필 "자본 비쌈·시간 자유" → 자본 deploy 항목 hard exclude. 단일 추천도 정렬 Top 10. v0.9에서:
1. 자본 deploy 항목도 가시화 — 어떤 자본 항목이 백킹/마감 시그널이 강한지 사용자가 직접 판단.
2. 짧은 활동(딸깍) / 자본 0 활동을 별도 카테고리로 분리해 한눈에 접근.
3. 카테고리 간 중복 허용 — 한 프로젝트가 종합/딸깍/자본X 모두 등장 가능.

## 변경 사항

### 1. 출력 모델 — 3 카테고리 × Top 10

| 카테고리 | 필터 | 정렬 |
|---|---|---|
| 종합 | 없음 (전체 후보) | 추천도 내림차순 |
| 딸깍 | 예상 소요 ≤ 10분 (회수 무관) | 추천도 내림차순 |
| 자본X | deposit/swap/stake/매수 0원 | 추천도 내림차순 |

각 카테고리 Top 10 → 총 최대 30 row. **중복 허용** — 한 프로젝트가 다중 카테고리에 등장 가능.

### 2. 후보 풀 + 추천도 산정 (hard exclude 해제)

- v0.8까지: 자본 deploy 요구 항목은 listing 단계에서 즉시 제외 (Skipped 섹션 기록).
- v0.9: **hard exclude 해제**. 모든 listing 항목이 후보로 진입.
- 자본 deploy 정보(예: deposit $30, stake $100)는 listing 또는 detail 단계에서 추출 → 자본X 필터 + row 본문 반영.

**추천도 산정**:
- 기존 시그널(백킹·펀딩·마감 임박·리서치 카운트) 기반 별점 룰(v0.7부터) 그대로.
- **자본 deploy 항목은 시그널 합계 후 -1별 경감점** (최저 ★).
- tie-breaker: 같은 별점이면 마감 임박순.

### 3. 태그 정의 (양성 표시만)

- `[딸깍]`: 예상 소요 시간 ≤ 10분. one-time/daily/weekly 무관. listing 또는 detail 단계에서 prompt가 시간 추정 — 페이지 명시 시간 우선, 미명시 시 LLM 합리적 추정(활동 복잡도 기반).
- `[자본X]`: deposit/swap/stake/매수 0원. gas 소액(<$5)은 자본 아님 — testnet faucet, social quest, waitlist 등이 [자본X] 해당.
- 둘 다 만족 → `[딸깍][자본X]`. 둘 다 아님 → 태그 없음.
- 자본 deploy 액수는 row 본문(할 일 설명)에 그대로 노출 — 예: `$30 stake 후 weekly quest`.

**보수적 판정 규칙**: 정보 부족 시 false negative 허용, false positive 회피 — 시간/자본이 명확하지 않으면 태그 미부착.

### 4. Row 포맷

라벨: **공식 → 링크**.

```
<a href="ACT_URL">링크</a> · <a href="SRC_URL">출처</a> — Nexus(NEXUS) - testnet faucet 클릭 (~5분)
추천도: ★★★★☆ [딸깍][자본X]
```

- 링크 묶음 (공식 URL 확보): `<a>링크</a> · <a>출처</a>`. 미확보 fallback: `<a>출처</a>` 단독.
- 추천도 라인: `추천도: <별점> <태그>`. 태그 없으면 별점만.
- 태그 자리: `[딸깍]` `[자본X]` 둘 다 양성이면 `[딸깍][자본X]` (공백 없이 붙임). 추천도-태그 사이엔 공백 1개.

### 5. 메시지 split — 카테고리별 3 메시지

cache(`cache/latest-digest.md`)에는 **통합본 저장** (3 카테고리 헤더+row 전체). `telegram_post`가 카테고리 separator로 split 후 3개 sendMessage 호출.

**Separator**: `===CATEGORY_SPLIT===` (단독 라인). prompt가 각 카테고리 사이에 이 separator 출력.

**구현**:
- `telegram_post.post()`가 본문을 separator 기준 1차 split → 각 chunk를 기존 `_split_message`로 2차 4096자 split → 순차 sendMessage 호출.
- separator는 메시지에 노출되지 않음 (split 후 버림).

**메시지 헤더**:
- 종합: `🪂 오늘의 에어드랍 — 종합 Top 10 (YYYY-MM-DD)`
- 딸깍: `⚡ 딸깍 Top 10 (10분 이내)`
- 자본X: `💸 자본X Top 10 (자본 0)`

### 6. 핀 섹션 위치

- 활성 핀 ≥ 1개일 때, **종합 카테고리 메시지의 prefix**로 노출 (v0.8과 동일 형태 — `📌 Pinned (N개)` 헤더 + 핀 row 박제 + `─────────────` 구분선).
- 딸깍/자본X 메시지엔 핀 미노출.
- 핀 0개면 종합 메시지도 곧바로 Top 10 헤더.

### 7. 후보 풀·detail enrichment 비용 변화

- listing fetch: 6 URL 병렬 (변동 없음).
- detail enrichment 대상: `union(종합 top10 ∪ 딸깍 top10 ∪ 자본X top10)`을 dedupe한 unique 프로젝트 — 이론 최대 30, 실제 중복 많아 ~15-25.
- 예상 routine 시간: ~5분 → ~7-8분. `CLAUDE_TIMEOUT_SEC=600` 그대로 충분 (마진 있음).

### 8. Pin snapshot 포맷 (`prompts/airdrop_pin.md`)

새 핀부터 v0.9 포맷:
```yaml
snapshot_md: |
  <a href="ACT_URL">링크</a> · <a href="SRC_URL">출처</a> — 프로젝트명(티커) - 할 일
```

- 라벨 "공식" → "링크".
- **태그(`[딸깍][자본X]`) 부착 안 함** — 핀은 사용자 추적 의도로 박제. 시간 지나면 태그 정확도 떨어지므로 추천도와 동일하게 핀에는 미포함.
- 기존 핀(`pinned.yaml` 현재 `pins: []`)은 마이그레이션 무필요.

### 9. 사용자 프로필 — 자본 정책 변경

- 이전: 자본 0 hard exclude.
- v0.9: 자본 0이 **기본 선호**지만 자본 항목도 가시화. 추천도 산정 시 자본 항목 -1별 경감점으로 미세 선호 반영.
- `prompts/airdrop_digest.md` 헤더 문구 수정: "자본 비쌈·시간 자유. 자본 deploy 회피 선호이나 종합 ranking엔 모두 포함 (-1별 경감)."

## 변경 없음 (v0.8 유지)

- HTML parse_mode + 400 fallback (`telegram_post.py`).
- WebFetch 6 URL 병렬 listing.
- 2-pass detail enrichment + airdrops.io `/visit/<코드>/` 채택 룰 (v0.8.4).
- 정규화 룰 (`airdrops.io/visit/...` 예외).
- cryptorank stale 가드.
- daily 1회 cron broadcast.
- 핀 명령은 Claude CLI 자연어 + `cache/latest-digest.md` 참조.

### 10.1 Skipped/excluded 섹션 제거 (v0.9.1, 사용자 요청)

사용자 요청 — broadcast 출력에서 Skipped/excluded 섹션 완전 제거. 운영 정보(fetch 실패, ROI 미달, 핀 만료 정리 등)는 prompt 내부 처리만 하고 사용자 출력에 노출 X. critical alert도 별도 채널(stderr 로그 등)로 분리 검토.

### 10. 출력 컨트랙트 (v0.9.1 smoke test 후 추가)

prompt 응답(stdout)은 **broadcast text 그 자체**여야 한다. LLM이 "출력 완료" / "요약" 같은 메타 narration으로 응답하면 그게 그대로 Telegram에 전송됨 (v0.9.0 첫 smoke test에서 발생, 416자 메타 요약 broadcast 사고).

prompt §5.9에 명시:
- 응답 첫 글자: 핀 prefix(`📌`) 또는 종합 헤더(`🪂`).
- 응답 마지막 줄: 자본X Top 10의 마지막 row.
- 메타 narration / 코드 fence / chat-style 톤 모두 금지.
- 최소 길이 1500자 (3 카테고리 × ~10 row × ~200자/row 기준).

`claude_runner.py`의 `MIN_OUTPUT_LEN`도 200 → 1500으로 상향하여 메타 요약 회귀를 즉시 catch.

## 부작용·리스크

- **detail enrichment 비용 증가**: ~10개 → ~15-25개. timeout 위험 낮지만 모니터링 필요.
- **자본 deploy 정보 추출 정확도**: listing 페이지에서 자본 액수/유형 명시 안 된 경우 [자본X] 판정이 LLM 추정에 의존. cryptorank/icodrops는 보통 명시, airdrops.io는 가끔 누락. **누락 시 보수적 — [자본X] 미부착** (false negative 허용, false positive 회피).
- **태그 거짓 부착 risk**: prompt가 시간/자본 부정확 추정 시 태그 잘못 부착. 실 운영 발견 시 prompt 보강.
- **3 메시지 분리 인지 부담**: 사용자가 매일 3개 메시지 수신. 종합이 가장 권위 있음, 딸깍/자본X는 reference.
- **메시지 separator 누락 risk**: prompt가 `===CATEGORY_SPLIT===` 출력 안 하면 전체가 한 메시지로 가서 4096자 자동 split됨 (헤더 row 중간 끊김 가능). prompt가 separator를 빠뜨리지 않도록 §5에서 강조 + 운영 시 첫 broadcast 확인.

## v0.9에서 다루지 않는 것

- 카테고리별 reply threading (Telegram thread API 복잡, 별도 메시지 3개로 충분).
- 자본 deploy 항목의 별도 카테고리 `[자본]` Top 10 — 사용자가 회피 선호라 dedicated 카테고리 무의미.
- 가중치 튜닝 (시그널별 가중치 조정) — 운영하며 별점 분포 보고 결정.
- 사용자 프로필 다중 선호 (예: 시간 부족 사용자) — 단일 프로필 가정 유지.
