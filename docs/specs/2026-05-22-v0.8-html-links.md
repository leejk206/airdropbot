# v0.8.0 — HTML 링크 포맷 (공식 · 출처)

**날짜**: 2026-05-22
**입력**: 사용자 요청 — v0.7 row의 `(링크 (긴_URL))` 접두사가 시각적으로 길고, aggregator로만 이동(airdrops.io 등). row를 짧게 + 가능하면 프로젝트 공식 사이트로 직접 이동.

## 변경 사항

### 1. Telegram parse_mode 활성화 (HTML)

- **이전 (v0.7)**: `telegram_post.py:47` payload에 parse_mode 없음 → plain text. URL은 자동 linkify되지만 본문에 풀 URL이 그대로 노출.
- **변경**: payload에 `"parse_mode": "HTML"` 추가. `<a href="URL">label</a>` 태그로 라벨만 노출 가능.

#### 1.1 400 fallback (안전망)

prompt가 잘못된 HTML 만들면 Telegram이 400 BAD_REQUEST 반환 → 메시지 전체 실패. 이를 막기 위해:

- 400 응답 수신 시 **parse_mode를 빼고 동일 chunk 재전송 1회**. plain text라도 도달 우선.
- 재전송도 실패하면 raise (기존 동작과 동일).
- 5xx retry(60초 후) 로직은 그대로 유지. 400 fallback은 5xx와 별도 분기.

### 2. Row 포맷 (출력)

#### 2.1 변경 (layout A)

- **이전 (v0.7)**:
  ```
  (링크 (https://airdrops.io/nexus)) Nexus(NEXUS) - testnet faucet 클릭
  추천도: ★★★★★
  ```

- **변경 (공식 URL 확보)**:
  ```
  <a href="https://nexus.xyz">공식</a> · <a href="https://airdrops.io/nexus">출처</a> — Nexus(NEXUS) - testnet faucet 클릭
  추천도: ★★★★★
  ```
  사용자 화면에서는 `공식 · 출처 — Nexus(NEXUS) - testnet faucet 클릭` 으로 보이고, `공식`/`출처` 텍스트가 각각 hyperlink.

- **변경 (공식 URL 미확보)**:
  ```
  <a href="https://airdrops.io/nexus">출처</a> — Nexus(NEXUS) - testnet faucet 클릭
  추천도: ★★★★★
  ```
  `공식 · ` 부분 생략. 출처 단독 노출.

#### 2.2 구분자·기호

- `공식` 과 `출처` 사이: ` · ` (공백 + U+00B7 middle dot + 공백).
- 링크 label 묶음과 프로젝트명 사이: ` — ` (공백 + em dash + 공백).
- 프로젝트명(티커)와 할 일 사이: ` - ` (공백 + hyphen + 공백). v0.7과 동일.

### 3. 공식 URL 추출 (2-pass WebFetch)

**1차 smoke test 결과 (2026-05-22)**: listing page만 fetch했을 때 공식 URL 확보율 0/10. 모든 aggregator의 메인 listing page는 본문 텍스트에 official URL을 노출하지 않고, 외부 링크 아이콘 또는 별도 detail page에 둠. 그래서 단일 pass로는 fallback만 발생.

**v0.8.1 보강 (2026-05-22)**: 2-pass 구조로 변경.

#### 3.1 Pass 1 — listing fetch (`prompts/airdrop_digest.md` §2)

기존 §2 그대로 — 6개 listing page 병렬 WebFetch + 후보 추출. **공식 URL은 이 단계에서 시도하지 않음** (어차피 listing page에 거의 없음).

WebFetch prompt에서 회수: 프로젝트명, 활동 유형, 자본/시간 요구, 백킹, 마감, **source_url(detail page deep link)**. 공식 URL은 추출 시도 안 함.

#### 3.2 정렬·필터 (§3) — top 10 후보 확정

별점 산정 + 정렬 + dedupe → top 10 후보 리스트 확정. 이 단계까지는 공식 URL 없음.

#### 3.3 Pass 2 — detail page enrichment (신설, §3.5)

top 10 후보의 source_url 10개를 **단일 메시지에서 병렬 WebFetch**.

**v0.8.2 보강 (2026-05-23)**: 2차 smoke test에서 공식 URL 10/10 확보됐으나 **모두 도메인 root(홈페이지)**로 추출됨 → 사용자가 클릭해도 활동 페이지가 아닌 메인 페이지로 이동. 사용자 의도와 어긋남. 활동 URL 우선순위 강제 강화 필요.

**v0.8.3 진단·보강 (2026-05-23)**: 3차 smoke test로 5/10까지 개선됐으나 cryptorank Konnex가 여전히 홈으로 감. WebFetch로 cryptorank 페이지 직접 조사 결과:

| 라벨 | URL 종류 |
|------|---------|
| Website | 홈 |
| **Start activity** | **실제 활동 URL** |
| **Go to Form** | 보조 활동 URL |

cryptorank의 핵심 라벨 `Start activity` / `Go to Form`이 prompt 라벨 리스트에서 빠져 있어 LLM이 "Website"만 채택. icodrops도 `Claim` / `Stake (Points Farming)` 라벨이 활동 URL. airdrops.io는 활동 URL을 본질적으로 노출하지 않음 (홈 fallback 수용).

→ prompt에 aggregator별 핵심 라벨 명시 + "Website 라벨에 끌리지 말 것" 강제. subdomain 패턴(`claim.<x>`, `hub.<x>`, `learn.<x>`, `app.<x>` 등)도 1순위 힌트로 추가.

각 WebFetch prompt는 다음을 강제:

- **1순위 — 활동 직접 URL**. 다양한 라벨 ("Action" / "Activity URL" / "Claim URL" / "Quest URL" / "Form URL" / "How to participate" / "Participate" / "참여 링크" 등) + CTA 버튼 href + **외부 quest/폼 플랫폼 화이트리스트** (galxe / zealy / layer3 / guild / questn / forms.gle / typeform / tally / claim.<x> / app.<x> / testnet.<x> / faucet.<x> 등). 이 라벨/도메인에 매치되면 즉시 채택.
- **2순위 — 프로젝트 홈페이지** (1순위 fallback). "Website" 라벨 등.
- **3순위 — X(트위터)**, **4순위 — Discord**.

**도메인 root 판단 규칙**:
- 추출 URL이 도메인 root(`https://x.com/`) → 거의 항상 2순위(홈페이지). 한 번 더 페이지 훑어 1순위 후보 찾기 시도.
- path 있는 URL(`https://x.com/claim`) → 1순위 후보 가능성 높음, 채택 우선.

**v0.8.4 진단·보강 (2026-05-23)**: 4차 smoke test에서 활동 URL 4/10 확보 (Sui/Konnex/Monetrix/Grass), 4/10이 홈으로 빠짐(K25.ai/Beep/Kash/Charms), 2/10 null. 홈으로 빠진 4건의 detail page를 직접 WebFetch로 조사:

| 프로젝트 | aggregator | 실제 detail page 활동 라벨 | 실제 활동 href |
|---|---|---|---|
| K25.ai | cryptorank | `Join Waitlist` | `https://k25.ai/` (활동=홈, 이메일 폼) |
| Beep | airdrops.io | `Join points campaign` | `/visit/fo93/` (airdrops.io redirect) |
| Kash | airdrops.io | `Join now` | `/visit/5r93/` (airdrops.io redirect) |
| Charms | airdrops.io | `Join now` | `/visit/um93/` (airdrops.io redirect) |

→ **K25.ai는 활동 = 홈 그 자체** (이메일 입력만으로 끝). 개선 불가, holding.

→ **airdrops.io는 자체 redirect path `/visit/<코드>/` 형태로 활동 URL 노출**. 3건 모두 동일 패턴. 이전 prompt는 두 가지 이슈로 이 redirect를 놓침:
  1. `Join now` / `Join points campaign` 라벨이 §3.3에 명시돼 있었으나 LLM이 "Website" 라벨 redirect를 더 우선했음 — `Join now` 강조 부족.
  2. §3.3.1 정규화 룰("aggregator 자체 도메인 추출 시 null")이 `airdrops.io/visit/...` path를 무효화할 위험 존재. 명시적 예외 필요.

→ prompt에 다음 보강:
  - airdrops.io는 활동 URL이 항상 `/visit/<짧은코드>/` 형태임을 1차 명시. `Join now` / `Join points campaign` / `Visit Activity` 라벨 redirect를 즉시 채택.
  - "Website" 라벨이 가리키는 `/visit/<코드>/`는 홈 redirect임을 명시, 채택 금지.
  - §3.3.1 정규화 룰에 예외 추가: `https://airdrops.io/visit/<코드>/` 형태는 source(`https://airdrops.io/<project>/`)와 path가 다르므로 null 처리 금지.

기대 개선: 4/10 → 7/10 (Beep/Kash/Charms).

#### 3.3.1 정규화 (v0.8.4 보강)

aggregator 자체 URL이 추출되면 **그건 source와 동일하므로 무효** → null로 normalize. 즉 official_url == source의 host와 같으면 null.

**예외**: `https://airdrops.io/visit/<짧은코드>/` 형태는 host가 airdrops.io여도 활동 redirect URL이므로 채택 (null 금지). source path와 완전히 같은 경우만 null.

#### 3.4 fallback

10개 후보 중 detail 페이지가 공식 URL 노출 안 했거나, fetch 실패한 항목은 `official_url=null` → 출력 row는 §2.1 fallback (출처 단독).

#### 3.5 비용

- Pass 1: 6 fetch (병렬, 변동 없음)
- Pass 2: 10 fetch (병렬, 신규)
- 예상 routine 시간: 기존 4분 → 5-6분.

### 4. HTML 이스케이프 룰

Telegram HTML mode 요구사항:
- `&` → `&amp;`
- `<` → `&lt;`
- `>` → `&gt;`

prompt가 출력 생성 시 텍스트 영역(프로젝트명/티커/할 일)에 위 3개 문자 있으면 이스케이프. 일반적 프로젝트명에는 거의 안 들어가지만 가드 명시.

href 속성 안 URL은 원본 그대로 (Telegram 실측상 raw `&` 허용). 깨지면 400 → §1.1 fallback.

허용되는 HTML 태그: **`<a href="...">...</a>` 만**. 그 외(`<b>`, `<i>`, `<code>` 등) 사용 금지 — 디자인 일관성 + 환각 방지.

### 5. 핀 snapshot 정규화 (airdrop_pin.md §6)

snapshot_md도 새 포맷 따름:
```
<a href="<official_url 또는 source_url>">공식</a> · <a href="<source_url>">출처</a> — <프로젝트명>(<티커>) - <할 일>
```

공식 URL 없는 경우 §2.1 fallback과 동일하게 `출처` 단독.

기존 핀(`pinned.yaml` 현재 `pins: []`)이 없으므로 마이그레이션 무필요. 새로 추가되는 핀부터 v0.8 포맷.

### 6. 헤더·기타

- Top 10 헤더: v0.7과 동일 (`🪂 오늘의 에어드랍 Top 10 — 추천도순 (YYYY-MM-DD)`).
- Pinned 헤더: v0.7과 동일 (`📌 Pinned (<N>개)`).
- 정렬·필터·별점 산정 룰: v0.7과 동일.

## 변경 없음 (v0.7과 동일)

- 자본=없음 hard exclude.
- 별점 5단계 + 정렬(추천도 내림차순 + 마감 임박 tie-breaker).
- WebFetch 6 URL 병렬.
- daily 1회 cron broadcast.
- pin 명령은 Claude CLI 자연어 + `cache/latest-digest.md` 참조.

## v0.8에서 다루지 않는 것

- URL shortener (bit.ly 등) — 외부 의존·추적 우려, 사용 안 함. HTML hyperlink로 충분.
- MarkdownV2 mode — 이스케이프 부담이 너무 큼(`.`, `-`, `(`, `)` 등 다수). HTML이 더 안전.
- 공식 URL 자동 검증(WebSearch ping 등) — 추가 호출 비용 + 환각 risk 더 큼. prompt 정직성에 의존.

## 부작용·리스크

- **HTML 파싱 실패 가능성**: prompt가 비정상 태그 생성 시 메시지 전체 안 도달. **§1.1 400 fallback으로 plain text 보장**.
- **fallback 시 가독성**: parse_mode 빠지면 `<a href="...">공식</a>` 원문이 그대로 노출되어 매우 보기 흉함. 사용자 알람 + 다음 broadcast에서 prompt 보완 신호로 활용.
- **공식 URL 환각 risk**: prompt에 "페이지에 명시된 것만" 강조. 위반 시 fake 링크 → 사용자가 잘못된 사이트 이동 risk. broadcast 후 사용자가 1-2개 sanity check 권장.
